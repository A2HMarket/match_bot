# P38 Agent 设计审查与修复

审查范围：入站执行租约与消息幂等、任务规划和条件编译、场景工具装配、来源匹配与证据校验、工具重试、最终交付、会话和审批恢复。代码基于 P37，agent 版本升为 0.25.0，无新依赖、数据库迁移或出站通道。

## 已修复的确定性缺陷

| 层 | 缺陷 | 修复 |
| --- | --- | --- |
| 证据校验 | 数字片段比较不认识 6pm/18:00、1,600/1600、December/12月、ISO 日期中的月份 | 独立的数字表达归一化模块；时钟和月份使用类型标记，不能由无关数字证明；保留事实归属和 JEV 校验 |
| 规划 | 明确“最好”的偏好可被模型提交成硬条件 | 用当前用户原句的修饰语约束 strength，不把偏好跨越“但”传播到硬预算 |
| 规划 | 总预算计入 bills 可被另造为“房源租金必须含 bills”的布尔硬条件 | 拒绝已识别的布尔预算 scope 别名并返回字段纠错；提示词明确 budget 的总额口径与 bills 的租金包含条件是不同字段 |
| 主体匹配 | “周末羽毛球搭子”整句被要求出现在来源里 | 从活动标题分离已单独编译的时间、区域、水平修饰及角色后缀；条件仍独立检查，网球等其他主体不能因此匹配 |
| 执行 | 规划失败的短句补充被无条件静默忽略 | 规划失败进入原有受控状态回复路径；不把内部错误当作用户无需答复 |
| 收尾 | 研究轮数耗尽直接兜底，已有资料没有收尾机会 | 未被出站拒绝且证据重试未耗尽时，进入已有的有限收尾阶段；保留总时间上限、最多 3 轮和所有出站校验 |
| SDK 协议 | 必须调用工具的设置在第一次调用后默认重置 | 规划、收尾和固定状态阶段显式关闭 resetToolChoice；普通执行保持原行为 |
| 收尾上下文 | 失败 run 未保存工具历史时，新收尾拿不到具体拒绝原因 | 当前请求上下文保留有界 validationFeedback，以低优先级数据包交给收尾；成功生成有效草稿后清除 |
| 终止协议 | react 已经成功入队，但终止判断没有包含它，仍继续请求模型；合法 no-op 也依赖模型再说一次结束 | 成功 react 与返回 ok 的 do_nothing 立即终止；可行动请求拒绝静默的工具结果仍继续处理 |

收尾允许修正参数/证据错误，不允许绕过真实出站拒绝。反馈要求移除无法证明的数字、已回答或未登记的问题、被排除的来源；不要求模型为提升通过率放宽用户条件。

## 保留并复核的边界

- 所有发送仍经原出站工具、Phase 规则、审批与出站表；未添加直接发送或第三方联系能力。
- 任务状态与条件仅来自当前用户和当前 chat/channel 作用域；架构测试覆盖跨用户、跨聊天数据排除。
- 证据匹配不等于用户目标已实现，完成仍需用户确认。数值归一化也不等于整句话真实，来源归属和语义检查仍保留。
- 审批快照继续校验版本、归属与执行状态，版本升级后旧快照不能盲目恢复。
- 真实模型测试采用本地隔离数据库、合成用户及模拟发送，没有 Telegram 外发。

## 验证和限制

新增回归先失败后修复；完整 `pnpm check` 通过：**135 个测试文件，1174 项测试**。包括现有审批、出站幂等、任务状态、作用域隔离和 SDK 测试。

第一次全量检查因测试环境失败：队列用的是 `TEST_REDIS_URL`，而非仅 `REDIS_URL`；部分数据库测试假定出站表为空，之前真实模型记录不符合这个前提。改用独立空库 `matchbot_p38_check` 和明确的测试 Redis 库后重新全量通过，没有修改或跳过断言。

真实网页复测中，美术馆成功交付带来源的开放时间与门票说明；药房成功交付部分资料并明确未查清营业时间。这两项此前两种模型均只得到固定兜底。药房仍不是完整需求交付，不能计为全部事实已经查清。

真实多轮结果见 [P38 live summary](2026-10-18-p38-live-summary.json)。保留中间失败运行，不用后一次结果覆盖前一次；修复过程中运行的源码指纹不同。

最后一组同源码指纹 `6a223da97a573546ac0fbf3709dd9e625309d5fefe9e0e86a862c5927e5863d8` 的 GPT low 五轮会话：桌椅 4/5、租房 5/5、羽毛球 5/5，合计 **14/15**，此前 P37 为 12/15。唯一评分失败为桌椅第二轮：实际发送了询问出发车站/地标和出行方式的澄清，而评分器要求该轮必须再次带来源。保留失败分数，不将其改记为通过。租房已能保留待核实线索，并明确账单未知、不能认定满足总上限。较早中间版本的 DeepSeek 为 13/15，仍有无根据断言、重复问题被拦截；不将不同代码指纹合并为同一版本成功率。

上述最后一组运行还暴露了完成确认的空转，随后单独修复终止协议。对这一最终增量，新增 react/no-op 单次调用回归，并真实运行“谢谢”：只发生 1 次规划和 1 次表情工具生成，约 6.1 秒完成，未再空转。没有把此前整组多轮冒充为终止补丁之后的全量真实运行。单次小样本也不能证明稳定成功率。

## 尚不能宣称解决的设计风险

- 任意 custom 条件的语义仍依赖模型；本次修复已确认的字段和强度错误，不等于全面完成自然语言条件验证。
- JEV 对未知/冲突的判断仍有波动和不可用风险。不得通过降低拒绝阈值掩盖这些情况。
- 当前输入包有字符预算，但所有工具历史仍未形成统一的 token 预算；还需要独立的长会话负载验证。
- 现有质量评分会把有必要的澄清也记成“未交付来源”，同时可能漏掉自由文本里的不当建议。保留原始自动分数，并分别报告人工判读，不现场改评分器提高分数。
- 本次没有做真实 Telegram、云端多租户压力测试，也没有独立证明兼容接口后端的模型身份。隔离/审批回归通过不能替代部署验收。
