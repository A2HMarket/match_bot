## 实现

- record_task_progress给出与出站代码同源的可用refs、待核实项和排除项；混合提交无效候选时返回可纠正的选择反馈，不自动删改回答，不重试已被Jev拒绝的推荐。所有原门和阈值保留。
- confirmTaskOutcome统一准备验证与仓储应用。所有required分项已分别由本人确认完成时，整体完成且原子关闭关联Demand；未解决分项不关闭，用户自行买到不冒充来源验证。结果确认失败时返回受信校验反馈，帮助规划器纠正“已解决/取消”的解释。
- 明确“总预算不能增加”而模型只提交账单偏好时，单个既有住房月预算保留金额并改为all_in；单纯最好包账单不改变预算范围。条件来源仍为本人原句。
- 朋友式回答强调搬运/位置/卖家关系的未知，不能由可拆卸推出用户能单人搬、由同区推出一次取完，也不能劝用户突破硬预算。
- 初学者冲突规则补上“不接受初学者/零基础”“谢绝新手”“仅限中级”等明确措辞。仍有“要求三年以上经验”的帖子混入备选，未宣称技能冲突整体修复。
- 出站来源证据补入对应发布时间及伦敦核对日期。原先只传标题正文，不能支持模型转述“昨天发布”；转载时间未知时不拿转载创建时间冒充原帖时间。补齐字段不意味着已证明所有Jev拒绝都由这一因素造成。

没有新增个人数据字段、依赖、公开出站路径或门禁豁免；跨domain/db/agent/eval属于同一任务确认/推荐契约。既有30天任务与7天快照保留规则不变。迁移14本轮补应用隔离预览库；业务库不变。
