# 回答风格清理与主动承担（2026-10-18）

## 改动与来源

Agent 0.20.0。用户要求先尽力做事、少指派任务，移除技术化的匹配/核验话术。此次实现仅packages/agent，另有计划/评测脚本，无表、依赖、权限或出站动作变更。

清理的冲突来源：request-instructions曾要求“建议你先问/你可以确认”，同时强制市场正文仅两句/200字并由代码追加详细卡片；reply-to-request又在no_match/unavailable前固定拼接匹配判定；market-choice-presentation每轮追加“尚未确认完全匹配/备选/待确认”等报告字段；request-status在失败后按品类制造新问题或核对清单。工具说明和SOUL示例也含默认交接、代联络口吻和公开群询问症状的冲突。

现在表达原则放SOUL，业务提示只保留工具选择、证据/硬条件/权限/任务绑定与必要的输出契约。明确公开信息由agent读详情、已存来源和针对性补搜，用户问题只用于未回答的个人条件或决策。没有增加代联络、下单或后台监控能力。

默认市场正文由模型说明事实、比较与真正影响选择的未知（700字上限），代码只追加命名来源、短报价和原文明确的损坏提醒；展开时才显示详情。内部unknown不再被代码翻译成“帖子没写”，因为解析未命中不等于原文缺失。内部条件、排除和出站判定仍保留。m编号会替换为选中物品名；未选中的行内编号直接拒绝，不悄悄删除。固定状态只会附加已经规划且仍未回答的个人条件问题，并保留预算等正确账本键；不会因推荐失败就发待办清单。
