## 根因与证据

### 1. 问号被当成向用户索取条件，产生系统性误拦

`packages/agent/src/task-outbound.ts` 用 `/[?？]/` 判断是否在追问，再要求 next action=ask_user 和 constraintKey；若该条件已知，则拒绝。`reply_to_request` 在事实修复前先做这个检查。本轮 outbound_input 共28条拒绝，其中11条要求先登记问题、12条称条件已回答。不能把23条全部归为误判：其中也有真正不必要的追问；但下列误判可以由调用参数直接确认。

打印机的未发送草稿有：“问的时候可以直接说：『HP 那台激光打印机还在吗？型号是什么，碳粉大概还剩多少？』”。这是建议用户问卖家的示例，被当成 Bot 在向用户追问而拒绝。它连续改写三次、耗尽输入重试后，只发了固定状态。两层问题并存：代码误判，以及草稿本身仍喜欢把查证交回用户。**解除误拦不等于草稿质量已合格。**

后续“要不要我按激光+无线再找一轮？”、“要不要我帮你确认线上表要填哪些项？”也反映主动性不足：用户已表达目标，允许的只读补查不应再反复请求许可。

### 2. 来源与账本契约不顺，研究结果没有稳定变成可交付证据

看展首轮实际做了主题发现和展名补查，但连续4次 record_task_progress 失败为 `unknown or unread source reference`，第5次 budget_exhausted；回答又因 refs 超过 schema 上限被拒。第二轮出现引文不在原文，修正后可登记；`£0` 与“免费”的数值表达也触发不支持数值拒绝。当前不得据此声称原始草稿事实全对；引用与数值契约需要各自冻结复现。

市场场景反复把 computed unknown 当 supported，引发账本价格/区域校验失败；租房补充新条件后，详情读取因此前已尝试而拒绝，模型没有选新的研究路径。需要把“没有新来源”和“没法向用户交付”分开诊断。

### 3. Jev 不是本轮大多数空答的直接原因，但有一次合理语义拒绝

10次固定状态主要发生在输入契约、来源登记或答案生成失败之后，最终状态均按既有路径通过。不能笼统说“都是 Jev 拦住”。看展第二轮另有一次真正出站 drop：mentionsUnverified=0.58；原草稿先把周六成人£25、超预算的展称为“最稳”，再建议改周日到周四；还含未经独立确认的儿童适合度判断。该拒绝不能靠放宽阈值消除。

羽毛球未发送草稿仍把“新生老手都有”解释成适合新手，还猜测组织是否“凑人数”。这些是内容质量风险，不是门挡住好答案的证据。

### 4. 价格卡和正文不一致

租房唯一发出的首轮正文说£350计价单位不明，来源卡却标£350/月。正文还通过假设周租来判断可能在预算内。应在同一证据解释下生成正文和卡片；计价单位未知时不能让卡片给出确定月租，亦不能把假设计价当预算满足。

### 5. 固定状态掩盖失败，成本主要消耗在修复循环

13条发言发生109次Main模型调用；打印机两轮共约41.2万token，用户却只收到两句一样的话。没有发生真正沉默，但任务没有推进。当前固定状态被用于多种内部失败，用户会误以为“没有线索”，而实际常已有搜索结果。修复应保留现有出站门：能校验的部分答复仍走正常工具；无法安全生成时，固定状态应准确反映受阻类型，不能把自由事实塞进状态路径绕门。

## 下一轮优先级（本批未实施）

1. 用本轮真实工具参数冻结回归：区分真正向用户索取条件、引用第三方问句、修辞问句；不要仅靠问号。只验证真实必要、未回答的个人条件，不能通过删标点绕过校验。
2. 打通 source ref / passage ref / XHS note ref 到任务账本的边界；工具返回可用引用与重要未决项。针对相同错误的重复修复设有限且有信息增益的路径，不继续喂整段上下文重写。
3. 每个新硬条件先更新过滤与研究计划，遇到旧详情读尽就扩新关键词/实体或转适当网页来源。可自行补查的未知先查，不能假装联系贴主；确实只有贴主知道时说清能力边界并提供可用线索，而非许诺后台跟进。
4. 正文、价格卡、账本使用一致的价格单位和证据；正常答案允许诚实有用的部分结果，但继续排除明确冲突、未经证实的事实和改写用户硬条件。
5. 在修改后重跑同一批冻结场景，分别记录主动研究、必要追问、用户需要再做的步骤、实质答复、成本；保留本次失败作为基线，不把“少说技术话”的字符串测试当人感提升。
